## S071 SSD INT8 collapse — root cause FOUND (calibration feed range), 2026-11-12

User asked to VERIFY the S070 INT8-collapse before committing to a path.
Reproduced it in the CUDA env (`model-experiments-cuda`, torch 2.11.0+cu128,
MCT 2.5.1, RTX Spark N1X cap 12.1) on the SAME ep29 weights + the six CAM-0100
robin crops (12-03-37..47, pulled from imagebank `/raw/CAM-0100/2026-11-12/`).
Script: `04-training/runs/ssd-mbv3/robin_regress.py`.

VERIFIED:
- **Float baseline reproduces S070's numbers EXACTLY**: robin
  0.3735/0.3631/0.0307/0.2595/0.3657/0.1412 on the six crops. Pipeline faithful.
- **INT8 PTQ, calibration feed [0,255]** (quantize.py's documented feed): every
  class best score = 0.0078 (=1/128, the u8 output floor) on ALL six — the exact
  S070 "catastrophic collapse". Confirmed as fact.

ROOT CAUSE (S070 had the right symptom, wrong cause):
`representative_dataset` in `lib/quantize.py` feeds RAW [0,255] to MCT, but
`SSDExport.forward` expects [0,1] (it does `(x-0.5)/0.5`). MCT calibrated the
quantizers to garbage activation ranges → softmax output clamps to the u8 floor.
S070's variant list (NOCLIPPING, GPTQ, mixed precision, ...) never fixed the
feed range, so it concluded "replace the deployment graph". It doesn't need to.

**INT8 PTQ, calibration feed [0,1]** (the graph's true input range): collapse
GONE. robin = 0.0742/0.0117/0.0586/0.1289/0.1172 (present 5/6, near-top 3/6),
blue tit wins crops 37/43. Functional, NOT float-parity: scores ~⅓ of float and
ranking shifts (residual PTQ accuracy loss — real but not catastrophic).

CAVEATS (do not over-claim):
- Verified the MCT-quantized forward (dequantized values now spread), NOT the
  on-sensor rpk. Sensor still emits u8 × 0.0078125.
