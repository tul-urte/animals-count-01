### S070 robin investigation — the deployment model, not the camera pipeline (2026-11-12)

The six forced-capture CAM-0100 images (12:03:37..47) were compared on their
exact historical ROI `(1272,1160,1690,1690)` -> image `[511,0,1590,1080]`.
The bank assessor (float ep29) found robin at 0.3735/0.3631/0.0307/0.2595/
0.3657/0.1412. The two misses at production 0.25 are real threshold/framing
misses; ROI inference scores the last at 0.674. Aspect-preserving letterbox is
WORSE (0.0047/0.0077) than the training-matched stretch.

The controlled artifact comparison used the original `ssd-mbv3_ep29.pt`, the
original MCT 2.5.1 environment, 100-image fixed representative recipe, and
SSDExport. The resulting quantized PyTorch model gives EVERY class best score
0.00781 on ALL SIX exact ROI crops — the exact live node signature (0.0078125).
Float ROI scores are meaningful (e.g. 0.1554 and 0.674 on first/last), so this
is strong evidence of a catastrophic MCT INT8/deployment confidence collapse,
not missed geometry or a broken capture/decode chain. Normal threshold lowering
cannot recover the robin; zero threshold merely admits generic background boxes.

An optional direct saved-pixel rpk confirmation was attempted using the new
`diagnostics/inject_image.py` (not deployed to production). It found the
OpenEXR API differences and the official memfd/CnnEnableInputTensor contract,
but the bounded final probe did not complete. The diagnostic was stopped,
temporary files removed, SUSPENDED=0, and the normal animals detector verified
running. No inference result from that optional probe is claimed; the offline
MCT comparison is the evidence. No workflow or production thresholds changed.

Next: investigate MCT quantization strategy on the SAME weights (especially
activation ranges/softmax output calibration and channel settings), then compare
against the float baseline. The assessor's full-vs-ROI policy and discard_after=1
remain separate recall-work items; these images are entering normal claim/edit
GT review, not being adopted with the generic near-zero camera boxes.

### S070 quantization strategy investigation (2026-11-12)

Tested the exact ep29 SSD weights in the original WSL MCT 2.5.1 / edge-mdt-tpc
1.3.0 / imx500-converter 3.18.2 environment, using the six saved robin ROI crops
as a regression set. No production model/config was changed.

FAILED variants (all offline, measured pre-threshold):
- default PTQ: every class best score 0.00781 on all six;
- NOCLIPPING + shift_negative_activation_correction=False: mostly 0.00781, a few
  0.01562, no useful robin;
- float final softmax override: small nonuniform outputs, no robin;
- float classification head (activation + weights override): same collapsed
  semantic output;
- mixed precision with 16-bit activation candidates, total_memory=4 MB: no
  recovery;
- uniform activation quantization + NOCLIPPING/no SNC: same;
- no bias correction / no negative correction / no linear/residual collapsing:
  same;
- one-epoch GPTQ (small LR): same;
- host softmax over raw logits: high-confidence WRONG classes (blue tit/starling),
  not a candidate;
- scaling probabilities x16/x128 before output quantization: no recovery.

The deployed package is the exact ep29 artifact (rpk MD5 matches). Its
`dnnParams.xml` exposes the broken output contract: classification tensor is
unsigned 8-bit with scale 0.0078125; boxes unsigned 8-bit scale 2.0. Hooks show
quantized logits still vary, but semantic ranking is wrong; this is not merely
softmax calibration. The current SSD INT8 artifact must not be used for normal
wildlife detection.

The earlier yololite ep5 control is not a replacement: high-confidence blackbird
on the six robin crops, no robin. It remains an undertrained historical baseline.

Recommended next phase: replace the SSD deployment graph with a known-good
IMX500 detector/export (or a supported split with host-side classification),
then evaluate on the six-image regression set before offering a bundle. Do not
solve this with lower node thresholds. If continuing MCT, use a SEPARATE
CUDA-enabled environment: RTX Spark N1X (~31 GB VRAM) is visible in WSL, but the
original imx500-env has CPU-only torch 2.5.1. Preserve that environment for
known-good conversion; install/test any newer MCT/CUDA toolchain separately.
