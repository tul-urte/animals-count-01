**THE CRONTAB POST-MORTEM (a long-standing estate trap finally killed)**:
the Pi's crontab carried LITERAL `\r\r` two-char sequences (backslash-r
backslash-r as TEXT, from an old Windows-side `crontab -` write in a
prior session   " od-proven on the spool file). Every line was
`...sh\r\r\n`. cron RAN most lines anyway (the trailing \r\r lands inside
the redirect args harmlessly) but it is a live grenade. Fixed
server-side: spool read as bytes   ' literal `\r` pairs stripped   '
`crontab /tmp/cron.fixed`   ' od-verified clean. The pi-side crontab is now
100% CR-free; any future Windows-side crontab write MUST go through
LF-verified files, never stdin text.
