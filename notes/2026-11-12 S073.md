**Clone hazard found and fixed:** the kit's `service.properties` template
ships **picods100's identity** (NODE_ID=picods_100, CAM_NO=100) and GRAPH at
the animals rpk (absent on a fresh card). A golden card built from the kit
would wake up wearing a real node's identity. install-base.sh now
neutralizes to NODE_ID=picods000-base / CAM_NO=000 / REBOOT_CODE=000 and
GRAPH=stock COCO rpk (which ships inside imx500-all). The verify ladder
caught this BEFORE it could ever go live - the ladder pays for itself.

**Script bugs the live run shook out** (all fixed in-repo, commits
19407d7/194e98e/c8b35aa):
- `set-node-identity.sh`: `${5:-}` empty-string-args trap (now: NO CLI args,
  env overrides only); `$_pp` unbound-variable on `set -u`; verify_rpk needs
  `--model` per role (COCO = the stock rpk, not the animals path); the
  bank-stage wrote to `/root/` (unreadable + wrong owner - moved to
  picods-tmp); the mover comment was appended twice (`ssh-keygen -y` already
  ends with the -C comment).
- `set-node-identity-finalize.sh` (NEW, phase B): must run **as root**
  (root-owned paths); the bank host key MUST be installed BEFORE the first
  rsync (StrictHostKeyChecking=yes); creds retrieval uses the RELATIVE
  rrsync path; the bank staging area is emptied via the same key.
- `register-node-on-bank.sh` (NEW, bank side from the workstation): no
  `sqlite3` CLI on the bank - use `sudo -n python3 -c "...sqlite3..."`;
  creds live at `/root/cutover-20261031/<node>.nodehome` (the rrsync-root
  guess was wrong); pscp to the bank needs `-hostkey` (or use OpenSSH scp,
  which is key-authed); ferry the imagebank host key with pscp `-hostkey`
  + `-pw` for the node.
- `install-base.sh`: kit payload self-extraction (extracts ONLY kit/ from
  the sibling tar.gz - never the embedded script copy, the byte-offset
  trap); tar.gz not zip (no unzip on a bare Lite image);
  `build-payload.sh` builds it (sibling layout, pyc-scrubbed).

**Process laws this session confirmed/added:**
- **Ship a script file, never inline `bash -c` through PowerShell/plink** -
  re-affirmed ~6 times; `$()`, parens, quotes, `||` all get mangled. This is
  now formalized in the new skill `.github/skills/rpi-from-windows/` (plink/
  pscp passwords, host-key revalidation on a reflash, one-time
  password-to-sudo bootstrap, sshd hang after failed-attempt bursts
  [wait ~45 s, retry once], password case-sensitivity [picods101's
  `acd101-pi` NOT `ACD101-PI`], dos2unix + CR-stripped md5-verify).
- **User runs the real install; the agent stages, verifies, and hands
  over.** The one step the user ran (install-base) went cleanest. The
  division of labor is now the commissioning default.
- **The verify ladder (verify-base.sh) is part of the deliverable**, not an
  extra: it caught the clone hazard + three script bugs on their first run.
  It ships beside install-base.sh for every future node.
