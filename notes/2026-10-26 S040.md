## S040    2026-10-26 (12:09  "12:27)    picods101 re-commissioned from a bare image   " the rebuild runbook, tested for real

**The ask**: picods101 was reflashed to a bare RPi OS Lite and is back on the network; re-commission it as a picods node, and since this is a chance to test the process, note where the S012 runbook could be improved. The user also asked whether a `raspi-config` pass is needed.

**Answer to the raspi-config question**: no. A headless camera node needs nothing from the raspi-config UI. The two things that matter are both set by file, not by the UI   " and both were already correct on the fresh image:
- **VPU/GPU carve-out**: the stock Lite image ships a 512 MB VPU split (`vc_mem.mem_size=0x20000000`, `gpu_mem` unset)   " identical to picods100, enough for the IMX500 ISP + NPU path at 2028 --1520. No edit, no reboot.
- **Power tweaks**: `powersave.sh` (tvservice --off, USB bus power, bluetooth off) is a *runtime* op the supervisor already runs at each start   " not boot config.
So: no raspi-config, no gpu_mem edit, no reboot. Everything is file-based and idempotent.

**What changed vs the S012 runbook (the improvements the test surfaced):**
1. **No model deploy for the COCO test bench.** The stock `imx500_network_ssd_mobilenetv2_fpnlite_320x320_pp.rpk` is installed by the `imx500-all` package at `/usr/share/imx500-models/` (md5 `7551501b   `, 80 COCO labels, `postprocess=None`). You only `scp` a model if you're deploying a *built* rpk (the animals-count `network.rpk`). For a stock-model node, step 5 of the S012 list (deploy model) is a no-op   " just point `GRAPH` at the stock path.
2. **The verification ladder is different for stock `_pp` models.** `infer.py` is *not* usable here: its decode picker requires a named `postprocess` and bails with `no decoder for postprocess=None`. The **demo's `else` branch** (imx500_object_detection_demo.py:409) is the production path for stock `_pp` rpks   " firmware already NMS'd, keep all rows, per-class gate. So "does inference work" on a COCO-SSD node is proven by **going live and watching the page**, not `infer.py`. The correct ladder for this node: `check_integration.py` (animals-ssd offline smoke) + `verify_rpk.py --model <coco>` (rpk loads, 80 labels, 320 --320) + the live page. (On an animals-model node `infer.py` is the right tool.)
3. **NAS CIFS credential is `acd100-pi`**, the imagebank user   " *not* the node password `acd101-pi`. I hit `mount error(22)` on the first try because I used the node password. Runbook fix: copy the fstab line verbatim from picods100 (base64 it to dodge the log masking) instead of retyping.
4. **Fresh trixie image is already current**   " `apt-get update`   ' 0 candidates. The 5 explicit python packages (`python3-picamera2/numpy/opencv/pil/lxml`) are still the imx500-all-independent set that must be added by hand (learned in S012, still true).
5. **`__pycache__/` ships in the kit** from the Windows tree (cpython-314 .pyc)   " delete it on the Pi; it's dead weight and can shadow the local bytecode.
6. **PowerShell   ' remote quoting is a recurring trap.** Inline `python3 -c "print('X')"` gets mangled (nested quotes), and `sudo` needs `-S -p ''` fed over stdin for a non-tty plink/ssh. The reliable pattern that worked end-to-end: write a small local script   ' `scp`   ' run remotely; for `sudo`, pipe the password to `sudo -S -p ''`. (plink worked for the password stage once the host key was re-validated with `-hostkey`; ssh key auth worked from the moment the Uhtred key was installed.)
