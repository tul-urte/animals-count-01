## S038    2026-10-26 (small hours, cont. 2)    queue triage flow: universal filters, image-to-image walking, reject-direct

**The user's design**: slice the queues (GT universe, dates...); from a queue item, move up/down the queue image-to-image with the filters still applied (paging the table, but image to image); reject directly from the claim page (auto-claim and reject). Decision: after reject-direct/publish, **land on the next image in the queue**.

**Universal filters** (querylib transform): every queue selecting `FROM workflow_state` gains `universe` / `day_from` / `day_to`   " auto-detected, no per-queue flags. The transform **wraps** the queue SQL as a subselect (a JOIN can't be appended after the `new` queue's GROUP BY   " the first attempt died on "near JOIN") and rewrites the queue's ORDER BY alias to the wrapper's (`w.`   ' `wq.`). All ten workflow queues got the filters with one code site.

**`queue_neighbors`** (querylib): the filtered+sorted queue's neighbours of one image_key   " `ROW_NUMBER() OVER (the queue's ORDER BY)` over the full filtered set, so the editor can walk image-to-image **across table page boundaries**. Powers both the bar and the post-action landing.

**The editor's queue bar**: `    queue        prev    new    1 of 1,791    next    `   " position within the same filtered queue, the ctx carried through every link. "not in this queue's current view" when the image just left it (rejected). **Reject-direct** on unclaimed new/assessed images: auto-claim   ' reject   ' **land on the next image**   " the full state machine runs, so the outcome row carries the user exactly like a manual reject. Publish with a ctx lands on the next too; release stays table-bound.

**The bug the live test flushed out** (three deploy iterations to find): POST form values are **plain strings** (`parse_qsl`) while the page code everywhere else uses the query-string's list convention   " `form.get("ctx", [""])[0]` indexed a *string*, taking its first character, so the queue context silently truncated to `/` and every landing fell back to home with a mystery. Fixed with a string/list-safe reader; also the next image is now computed **before** the reject/publish (the action removes this image from the queue, so the pre-action successor is the target).
