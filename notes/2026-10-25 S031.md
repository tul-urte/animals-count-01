## S031    2026-10-25 (night)    config page sliders + checkboxes, suspend/resume service control, live service indicator

**The user's asks**: numeric config fields as range sliders (e.g. `DETECTION_MIN_SCORE` 0  "1, step 0.05), booleans as checkboxes (e.g. `LOG_REJECTIONS`), a Suspend control for the service, Resume when suspended (via the service up-detector), and the home page's Live indicator following the service state live. Plan first, then execute.

**Sliders**   " every numeric hot key: `DETECTION_MIN_SCORE` (0  "1/0.05), `DETECTION_IOU` (0  "1/0.01), `DETECTION_SCORE_FLOOR` (0  "1/0.01), `DETECTION_MAX_ITEMS` (1  "50), `DETECTION_MAX_PER_LABEL` (0  "10), `DETECTION_MIN_AREA` (0  "2000/5), `DETECTION_MIN_EDGE` (0  "200), `MIN_LIGHT_LEVEL` + `MAX_LIGHT_LEVEL` (0  "100 %), `FULL_SENSOR_MAX_EDGE` (0  "4056/4), `FULL_SENSOR_EVERY` (0  "120 s/0.5), `LIVE_REFRESH_MS` (250  "10000/50). Each is a number box + range slider in lockstep (either drives the other); the number box stays the submitted form value so free entry within bounds still works. **Checkboxes**: `DETECTION_DROP_CONTAINED`, `LOG_DETECTIONS`, `LOG_REJECTIONS`   " unchecked boxes don't submit, so each carries a hidden `False` and the save loop takes the **last** submitted value (checked = `True`). Frames keep their preset dropdowns; `SENSOR_MODE` stays the restart-section dropdown.

**Caught in testing**: `MAX_LIGHT_LEVEL` was never on the page   " and it was **absent from cam.properties**, running at the demo's default 90. A naive page showed `0` and one save would have pinned the light-gate shut (light 37 > 0   ' the demo quits every frame). Fixes: the key is exposed (completing the light-gate pair), and `DEFAULTS` (mirroring the demo's `read_config`) shows absent keys' **effective** value   " the page and the save-compare both treat it as the pinned value now.

**Service control**: `service_stream(action)`   " one handshake generator for suspend/resume/restart, all on the up-detector (`demo_running()`). Suspend writes `SUSPENDED=1` and waits for the demo to actually exit; on stop-failure it **restores `SUSPENDED=0`** (the old restart code left the node down on abort). Resume writes `SUSPENDED=0` and waits for cron revival. Routes: `/suspend`, `/resume`, `/restart` (text streams) + `/service` (JSON `{running, suspended}`). The config page's Service control section picks the button from the detector (up   ' suspend, down   ' resume, restart always) and follows the stream live.

**Live indicator**: the home page's refresh loop polls `/service` each tick and drives the chip   " **Live** (dot on) / **Suspended** / **Down**; before this it was render-time `SUSPENDED` text, stale until a reload. The stats page's `service` row reads the same truth.

**Live-verified end-to-end on picods101** (detections flowing throughout): suspend   ' demo stopped in ~10 s (streamed, page reloaded); home chip flipped to Suspended with the dot off; config offered resume; resume   ' demo back in 55 s (cron), chip Live, fresh detections in a new session counter. Slider  "number sync and the save round-trip (`LIVE_REFRESH_MS` 1500  '2000  '1500, confirmed written + restored); checkbox saves both directions (`LOG_REJECTIONS` True  "False). `LOG_REJECTIONS` left **off** (the S029 investigation is closed).
