## S041   " GT-supply census page + dropdown/date filters (2026-10-26)

**The ask:** the user wants to prioritise publishing categories that are short in the ground truth. The GT queue should let them filter by category and see what is and is not present, with dropdowns for known value sets instead of free text. They mentioned browser localStorage or a user-filter table for persistence.

**What was built (3 new features, all live on imagebank):**

1. **GT-supply census page (`/gt/supply`)**   " per category in a chosen GT universe: `in GT` (ground-truth count), `assessed (ready)` (triage-queue count), `published` (confirmed so far). Sorted shortest-first so the zero-GT gaps float to the top. Each zero-GT category is flagged ("zero GT") with a one-click "publish   '" button that jumps to the assessed queue pre-filtered by that label and universe. Universe tabs (AnimalsCount/CocoTest). Home page links to it.

2. **Dynamic dropdowns for known value sets**   " `camera`, `label`, `gt_folder`, `user`, `universe` params across all 13 queues now render as ``select`` dropdowns populated from the DB (`SELECT DISTINCT` on the relevant column, universe-scoped when appropriate). Scores / free-text params stay ``input``.

3. **Date pickers for day_from/day_to**   " the two universal date-range filters now render as `<input type=date>` and validate (rejecting non-`YYYY-MM-DD` with a clean error page).

**Key implementation details:**
- `querylib.bind_values()`: added `date` type (blank = unconstrained, else must be `YYYY-MM-DD`); `enum` now skips `values` validation when `dynamic` is set (a dynamic enum had no static values, so it previously rejected every value).
- `ib_server._dynamic_options()`: new helper   " distinct non-empty values of a `table.col`, optionally universe-scoped (3 join strategies: native `gt_universe` column, `image_key` join to `images`, or unscoped for non-image-keyed tables like `detections`). Never raises.
- `_queue_param_form()`: renders ``select`` for `enum` (static or dynamic) and `<input type=date>` for `date`.
- `page_gt_supply()` / `_gt_supply_table()`: the census page + query (joins `ground_truth`, `workflow_state`, `image_status` via `images`).
- **Bug found + fixed here:** `_dynamic_options` raised `UnboundLocalError` when a non-image-keyed table (e.g. `detections.label`) was rendered under a universe filter   " `join` was only set in one branch but referenced unconditionally in the SQL template. Fixed (`join=""` in the fallback) + regression test added.

**Deploy tool committed (`06-deployment/imagebank/deploy.py`, tested end-to-end):** the manual deploy steps are now one command   " `python deploy.py` (deploy ib-server + restart + curl the key routes), with `--check` (safe local-vs-live diff), `--target harvest|both`, `--files    `, `--no-restart`, `--dry-run`. It drives scp/ssh via subprocess (explicit argv   " the PowerShell-mangling-safe pattern) and bakes in the traps hit while building it, so they are documented + handled rather than re-discovered:
- `Path.write_text` defaults to **CRLF on Windows**   ' the remote finalize script needs `newline="\n"` or `set -euo pipefail\r` breaks bash.
- **`__pycache__` can hold root-owned `.pyc`** (server runs as root)   ' plain `rm -rf` is permission-denied; use `sudo     || true` (a stale `.pyc` is invalidated by mtime anyway).
- **`run-server.sh` runs the server in the foreground**   ' never invoke it from an ssh session (hangs); `sudo pkill -f '[i]b_server.py'` + wait for the root-cron keep-alive to revive (poll `pgrep`, up to ~90s), with a detached `setsid` fallback.
- **md5-verify both sides with CR stripped BEFORE restarting**; abort (no restart) on mismatch.
- imagebank has **passwordless sudo** (`sudo -n true`).

`deploy.py --check` reports ib-server and harvest targets both **in sync**. Two extra fixes landed here that the earlier session-notes entry (S041 body) did not capture: the finalize-script CRLF fix and the root-owned `__pycache__` handling.
